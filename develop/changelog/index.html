    Changelog

    All notable changes to this project are documented in this file.

    The format is based on Keep a Changelog, and this project adheres to Semantic Versioning.

    Unreleased

    🔧 Fixed

    • BOM-only results files and BOM seqmaps in evaluation — a predictions file holding only a UTF-8 byte order mark made evaluate_mot_sequence raise No valid data found instead of scoring the sequence as having no predictions, because the emptiness check and the loader decoded the same bytes differently. A sequence map starting with a byte order mark put the mark into its first entry, so a header row was not recognised and the first sequence was looked up under a name with the mark. Both ignore a leading UTF-8 mark. An empty ground-truth file still raises. Unmarked seqmaps use the runtime's text encoding and fall back to UTF-8 if needed (#678).

    • Tuner handles a seqmap kept in gt_dir — a sequence map stored in the ground-truth folder under the name of a selected sequence was parsed as ground truth and aborted the study with Invalid MOT format. Preflight excludes the map and reports missing ground truth if no valid candidate exists. Trials use the sequence selection and ground-truth paths validated at construction, including when the map is edited or atomically saved. A leading UTF-8 byte order mark is ignored (#678).

    • XYXYStateEstimator covariance follows corner swaps under CMC — when an axis-aligned transform reflected the frame or the stored box was inverted, the corner states and velocities were relabelled but the covariance stayed on the original indices, so variances sat on the wrong edge and the Kalman gain was off. The covariance is now propagated with the same corner relabelling. The XYXY update applies when both off-diagonal coefficients have magnitude at most 1e-6, including when a reflection swaps edges of an upright box. Larger cross-axis terms leave the covariance unchanged. Centre-based estimators retain their existing update (#678).

    • Docs match current behaviour — the tuning guide now says ground-truth class column values below 1 are rejected and no -1 belongs there, the McByte rows describe mask-conditioned association as enabled only when the mask manager is on, iou_variant is documented as ignored by C-BIoU, trackers eval is documented as scoring CLEAR by default, and the evaluation guide covers skipped columns and empty results files (#678).

    • CLI help describes commands and their options — trackers --help shows command summaries. Run trackers <command> --help (for example, trackers track --help) for option descriptions. The new docstring-parser dependency lets jsonargparse read these descriptions from docstrings. Previously, track, eval, tune and download displayed Python function representations, and dataclass options showed only their type and default (#670).

    • Frames under non-ASCII paths on Windows — image-folder sources, MOT img1 frames and the trackers inspect commands failed to read or save images whose path had characters outside ASCII, such as an accented, Cyrillic or CJK folder name, because OpenCV reads Windows paths in the ANSI code page. These files are now read and written through NumPy and decoded or encoded with OpenCV.

    • CMC no longer swaps the corner velocities of a shrinking XYXYStateEstimator box — _warp_kalman_states sorted XYXY velocities per axis, so with BoTSORTTracker, McByteTracker or OCSORTTracker on the non-default XYXY estimator, every CMC step, even an identity transform, swapped a shrinking box's velocities and the filter predicted it growing. Velocities are no longer sorted: each is mapped through the linear part and stays with the corner that becomes the new edge, so for an upright box a warped velocity equals the motion of the warped box as long as one step does not invert the box. (#662)

    • MOT evaluation no longer silently drops ground-truth rows with a class below 1 — MOT15-style files, and the example in the evaluation docs, carry -1 in column 8, which the loader reads as the class. Those rows matched no scored class, so they were dropped with no warning: predictions identical to an all -1 file gave MOTA 0 and every prediction a false positive. evaluate_mot_sequence and evaluate_mot_sequences now raise ValueError when a row not marked ignored has a class below 1 that the class config does not name, and trackers eval exits 1 with that message. The message names the file and the classes, and gives a class_config value that scores those rows alongside the classes already scored. A file mixing class 1 with such rows used to return numbers for the class 1 rows only and now raises too. Classes of 1 and above, ignored rows and tracker files are not checked. trackers tune has no class_config option, so there the file has to be fixed (#661).

    • Evaluation tables no longer show uncomputed columns as zero — unavailable or misspelled columns are skipped with a warning naming them. Valid requested columns remain visible, and if none are valid the table uses available default columns. trackers eval --output still saves computed results (#660).

    • trackers eval scores a results file with no rows as a tracker that output nothing — a sequence where trackers track found no tracks writes such a file, and it used to raise ValueError and abort the whole benchmark. It now counts every scored ground-truth box as a miss and scores zero. A ground-truth file with no rows is still an error (#659).

    • MOT and detection files saved with a UTF-8 byte order mark now load — load_mot_file (used by trackers eval, trackers track, the tuner and ReID calibration) and the detection-file reader behind trackers benchmark and trackers inspect read the mark that Excel's "CSV UTF-8" export and some Windows editors put at the start of a file as part of the first frame number, so a valid gt.txt or det.txt failed with Invalid frame number or Could not parse detection line 1. Both readers now open files as utf-8-sig, which drops a leading mark and reads every other UTF-8 file unchanged.

    2.7.0 — 2026-11-05

    Trackers

    • OCSORTTracker camera motion compensation — opt-in enable_cmc / cmc_method / cmc_downscale, as on BoT-SORT and McByte. With enable_cmc=True and the frame passed to update(), the shared CMC estimate warps every track's Kalman state, stored observations (OCM/OCR/velocity) and frozen ORU state before association. Off by default, so defaults and benchmark numbers are unchanged. Contributor-reported validation runs with YOLOX detections gain on MOT17 and SportsMOT and lose slightly on DanceTrack, so leave it off for static cameras (#611).
    • BoTSORTTracker.update() takes a keyword-only cmc_transform — a per-frame 2x3 affine (previous to current frame, the CMC.estimate() convention) from external registration, applied in place of the internal estimate regardless of enable_cmc. Passing both frame and cmc_transform, or a malformed matrix (non-finite, 3x3, wrong shape), raises ValueError before any state change. CBIoUTracker.update() accepts it but ignores it with a UserWarning (#610, #609).
    • McByte cmc_downscale now defaults to 6 — median CMC latency halves versus 2 on the 45-clip 1280x720 SportsMOT validation split and passes the dataset-level mean/median quality criterion. Ground-truth detections, masks disabled; 9/45 clips regressed under the earlier strict per-clip gate. Pass cmc_downscale=2 for the previous behavior. CMCConfig and BoTSORTTracker stay at 2 (#538).
    • McByte skips mask-only association work when mask evidence is unavailable — clear-match locking and reduced assignment are kept (#573).
    • the mask stack (SAM generation, Cutie propagation, MaskManager) moved from trackers.core.mcbyte.masks to trackers.core.masks — since it is not McByte-specific (#543).
    • BoTSORTTracklet and McByteTracklet share scale-aware noise code in trackers.utils.scale_aware_tracklet.ScaleAwareNoiseTracklet (_diagonal_matrix moved to trackers.utils.matrix), and the BoT-SORT / C-BIoU / McByte noise refresh no longer decodes full boxes. No public API or output change (#596).
    • Deprecated: package-level MaskGenerator, MaskPropagator, MaskOutput, TrackletSnapshot and mask_manager.MaskManager keep deprecation shims until 3.0 — import from trackers.core.masks or trackers.core.masks.manager. Deep modules trackers.core.mcbyte.masks.{base,sam,cutie,dummy} are removed without shims (#543).
    • Fixed: OC-SORT observation-centric re-update (ORU) no longer corrupts XCYCWHStateEstimator tracks. It replayed interpolated boxes into the Kalman filter as raw [x1, y1, x2, y2], bypassing bbox_to_measurement, so re-acquisition after a miss left the posterior far from the detection ([81.9, 38.1, 217.2, 200.0] instead of [140, 100, 190, 200] for a 50x100 box after a two-frame miss) without an error. Virtual boxes are now encoded first. XCYCSRStateEstimator and XYXYStateEstimator output is bit-identical (#614).
    • Fixed: update() validates detections before mutating state — in all six trackers. A NaN/inf xyxy used to raise only after tracks were predicted and the timestamp anchor advanced (and, in ByteTrack, stage-1 matches applied and IDs allocated), leaving a retrying caller with aged or half-updated tracks. Low-confidence non-finite rows, silently ignored by OC-SORT, BoT-SORT, C-BIoU and McByte, now raise too (#613).
    • Fixed: empty update() results keep the input's data keys, mask, metadata and dtypes — instead of coming from sv.Detections.empty(); result.data["class_name"] no longer raises KeyError on empty frames. Non-empty results are unchanged (#638).
    • Fixed: BoTSORTTracker positional constructor parameter order from 2.6.1 is restored — correcting a development regression from #611 (#658).

    Re-ID

    • optional BoT-SORT appearance Re-ID — BoTSORTTracker(reid_model=..., reid_config=ReIDConfig(...)) takes an encoder object or model-source string. The trackers[reid] extra pins reid==0.1.0 and includes Matplotlib. Embeddings augment the first and unconfirmed association stages; the low-confidence second stage stays geometry-only. Off by default, needs a BGR frame on every update(), BoT-SORT only (#511, #655).
    • selectable fusion — ReIDConfig(fusion="botsort") takes the better geometric/appearance score; opt-in fusion="adaptive" adds appearance with a capped best-versus-runner-up margin bonus, adapted from Deep OC-SORT's appearance weighting (not a new tracker). Both gate appearance by distance 0.5 * (1 - cosine) (appearance_threshold=0.25) and standard-IoU proximity (proximity_threshold=0.5). Adaptive defaults: appearance_weight=0.75, adaptive_weight_cap=0.5. Its similarity can reach 2.25, so retune first/unconfirmed association thresholds when switching (#511).
    • tuning and analysis helpers in trackers.reid — ReIDEncoder, FeatureBank, embedding extraction, appearance similarity, balanced same/different-identity sampling, acceptance rates, ROC AUC, frame-gap sweeps and plots. Tuner adds per-run search_space, fixed_defaults (overridden by fixed_params) and opt-in cache_embeddings=False; conditional nested reid_config.* search fields need a fixed encoder and images_dir. CLI track and tune accept --reid.*; track also --tracker.reid_config.* (#511).

    Evaluation

    • MOT ground-truth classes come from a MOTClassConfig — the mot17 default, a mot20 preset that treats class 6 as a distractor, or a custom config. Accepted as class_config by evaluate_mot_sequence / evaluate_mot_sequences and as --class_config on trackers eval; a UserWarning fires when a MOT20 sequence is scored with mot17. Default MOT17 behavior is unchanged (#597, #598).
    • lower evaluation and prediction overhead — vectorized Identity ID remapping, fewer overlap temporaries and distractor-membership work, direct small diagonal covariance construction, and OC-SORT reuse of the predicted box. No fresh benchmark was run for these notes (#574, #576, #577, #578, #579, #580).
    • Fixed: unknown metric families are rejected before file I/O — use CLEAR, HOTA or Identity. The single-sequence path no longer returns empty metrics for unsupported names (#598).
    • Fixed: evaluate_mot_sequences no longer discovers hidden directories as MOT-layout sequences. The filter tested p.name, always gt.txt in <seq>/gt/gt.txt, so a hidden backup copy of a sequence was evaluated and aborted the run with FileNotFoundError: Tracker file not found: .../.MOT17-02-backup.txt. It now tests the sequence directory name, so a MOT-layout directory whose own name starts with . is no longer discovered; list it in a seqmap. Layout detection also skips hidden files, so a hidden .txt at the root of a MOT-layout gt_dir no longer fails with ValueError: No sequences found (#642).
    • Fixed: trackers eval names a <seq>/gt/gt.txt sequence <seq> instead of gt in the results table, SequenceResult.sequence and the --output JSON (relative paths resolve against the working directory). Other ground-truth files keep their stem. Scripts matching the literal gt need updating (#634, #635).

    CLI

    • Breaking: trackers.scripts is removed — use the trackers executable or python -m trackers.cli. Direct imports from the old implementation modules need migration (#413, #543).
    • Deprecated: legacy spellings (renamed track/detection/output/show/filter flags, long minimum_/maximum_ prefixes, old list forms, positional download dataset selection) warn and are removed in 2.10.0. Use the grouped interface and do not combine a legacy flag with its replacement. --tracker NAME stays as shorthand for --tracker.name NAME (#413, #552).
    • Deprecated: trackers eval --tracker / --tracker_dir are renamed --predictions / --predictions_dir — old spellings emit FutureWarning and are removed in 2.10.0 (#541).
    • grouped CLI and YAML configuration — jsonargparse replaces argparse, with --config and grouped --detection.*, --filters.*, --output.*, --show.* and tracker settings. The registry exposes IoU variants, state estimators and McByte mask configuration; hyphens/underscores normalize in option names and booleans accept explicit values. Python constructor parameter names are unchanged (#413, #552).
    • trackers benchmark mcbyte runs McByte over complete MOT17, DanceTrack, SportsMOT or SoccerNet-tracking test sets and writes MOTChallenge-format results. Flags cover dataset (--dataset), per-dataset detection/image roots (--dataset_roots), device, output location, CMC method/downscale, isolated mask matching, skip-existing and partial-result retention (#541, #543).
    • trackers inspect group for visual validation of the mask stack and McByte: inspect sam, inspect cutie, inspect mask-manager (from command-line boxes or a MOT ground-truth file) and inspect mcbyte (locked-IoU baseline against full mask-conditioned McByte). Each writes annotated frames into a timestamped run directory (#543).
    • CLI tracking initializes the tracker with a finite positive source FPS unless --tracker.frame_rate is set, correcting buffer/lifetime behavior on non-30-FPS input. Pass --tracker.frame_rate 30 for the previous setting (#569).

    Packaging & docs

    • Breaking: dependency floor — supervision>=0.31.0 replaces >=0.26.1, and the base install adds jsonargparse>=4.48.0,<5. Python stays >=3.10 (#413, #639).
    • three cookbooks linked from Tutorials: Re-ID with appearance-threshold analysis, BoT-SORT camera-motion compensation and McByte mask tracking. They target 2.7.0 and need the stated external models, datasets and optional dependencies (#511, #630).
    • documentation reorganized into usage, tuning, developer and evaluation sections — with CLI/migration, inspect and benchmark-runner guides, and the changelog and contribution guidance exposed on the site (#548, #549, #551, #553, #565).
    • development/documentation locks, pre-commit hooks and GitHub Actions updated — build CI selects Python 3.12, a build-job choice and not a Python minimum increase (#625, #648).

    2.6.1 — 2026-09-25

    Trackers

    • Fixed: GIoU no longer scores a malformed box above 0. _compute_iou_and_enclosing did not clamp box area, so a box inverted on both axes got a positive area, inflated the union past the enclosing area and turned GIoU's penalty into a bonus (over +29 on random malformed input, far outside [-1, 1]). Extents are now clamped at zero like the intersection. Affects GIoU only, reachable with iou=GIoU(); IoU/BIoU do not use the helper and DIoU/CIoU are byte-identical. Well-formed boxes are bit-identical (#589).
    • Fixed: OC-SORT returns detections below high_conf_det_threshold with tracker_id=-1 instead of dropping them, matching SORTTracker / ByteTrackTracker and the documented one-row-per-detection contract. Callers may see additional tracker_id == -1 rows (#566).
    • Fixed: McByte mask cleanup survives deferred delivery — removed tracklet IDs stay queued until the mask pipeline receives them, across skipped frames, duplicate timestamps and recoverable CUDA out-of-memory failures, including tracks pruned early during timestamp updates (#568).
    • Fixed: BoT-SORT and McByte refresh only the Kalman noise matrix the current step uses — Q on prediction, R on measurement update (#567).

    Motion & utilities

    • Fixed: batched xcycsr_to_xyxy decodes integer input to float64 — keeping fractional coordinates; float32 stays float32. Convert explicitly if you relied on the truncated integer dtype (#557).

    I/O & datasets

    • Fixed: image-directory frames use natural filename order (2.jpg before 10.jpg); zero-padded and non-numeric names keep their order (#558).

    Packaging & docs

    • Fixed: Mike-deployed documentation URLs (canonical, Open Graph, structured data, sitemap) point at the /latest/ alias without nesting the numbered version (#582).
    • McByte benchmark and comparison tables — tracker defaults, quickstart and evaluation guidance, dataset details, README terminology, search-result titles and video poster frames updated for this release (#539, #547, #555, #564, #583, #585, #587).

    2.6.0 — 2026-08-06

    Trackers

    • Breaking: invalid lost-track buffer settings raise ValueError — lost_track_buffer must be non-negative and frame_rate finite and positive for SORTTracker, ByteTrackTracker, OCSORTTracker, BoTSORTTracker and CBIoUTracker. lost_track_buffer=0 stays valid (no grace period) (#420).
    • Breaking: confirmed tracks survive one additional missed frame — all trackers changed from time_since_update < maximum_frames_without_update to <=, matching OC-SORT's earlier behavior. Expect small IDSW/HOTA shifts when comparing across this version (#420).
    • McByteTracker — mask-conditioned ByteTrack with SAM box-mask generation and Cutie propagation, exported with McByteMaskConfig and CLI-discoverable. New trackers[mask] extra installs torch, torchvision, rf-segment-anything and rf-cutie[inference] (now from PyPI, not git). Device defaults to "auto" (CUDA → MPS → CPU). Cutie is tunable through cutie_max_internal_size (480), cutie_mem_every (10) and cutie_use_long_term (True); cutie_channels_last, cutie_compile and AMP are off by default; minimum_mask_creation_frames (3) defers SAM/Cutie encoding for short-lived tracklets. Frames are RGB, unlike the BGR the other trackers expect. Mask checkpoints load with weights_only=True (CWE-502 guard) (#388, #418, #441, #452, #459, #481, #491, #508, #513, #519, #520, #521, #522, #523, #524, #525, #526, #529, #532).
    • optional timestamp= on BaseTracker.update() — all six trackers convert elapsed seconds into Kalman frame units and prune lost tracks on a seconds budget; without it, fixed-rate behavior is unchanged (#446).
    • bit-identical speedups — ~38% lower BoT-SORT/C-BIoU predict cost from cached transition/noise matrices and deferred DWNA calibration, predicted boxes cached across association stages, fewer Kalman-estimator copies, tidier OC-SORT association (#522, #527, #528).
    • Fixed: positive low-FPS lost_track_buffer values scale with ceil(...) instead of collapsing to zero, and confirmed tracks survive exactly the scaled number of missed frames (#420).
    • Fixed: BoT-SORT / C-BIoU first-frame tracks activated instantly are no longer dropped on a single miss — sticky maturity triggers once a real tracker_id is assigned, as in ByteTrack, removing a default-config ID switch (#478, #504).
    • Fixed: ByteTrack / BoT-SORT / C-BIoU return unmatched detections between high_conf_det_threshold and track_activation_threshold with tracker_id=-1 instead of dropping them, matching the update() contract. Callers may see additional tracker_id == -1 rows (#475).
    • Fixed: signed IoU variants are clamped to [0, 1] before score fusion — so CIoU's ~-1.5 floor no longer yields negative fused similarities; a no-op for GIoU/DIoU (#476).
    • Fixed: OC-SORT Kalman scale stays positive across frame-step gaps — clamp_velocity no longer lets it collapse negative over long timestamp gaps (#509).

    Motion & utilities

    • KalmanMotionModel in trackers.utils.motion_models supplies the Kalman F and Q for a given frame_step: a constant-velocity F (constant_velocity_F) and ScalableProcessNoise for the tuned Q, DWNA-scaled on timestamp gaps (#446).
    • CMC sparse optical-flow status-mask filtering is vectorized — ~24x faster for that operation, with bit-identical output (#522).
    • Fixed: CMC handles mid-stream resolution changes in optical-flow motion estimation with a re-sync/resize path (#505).
    • Fixed: CMC no longer crashes in cv2.resize on tiny downscaled images — dimensions clamp to max(1, ...), covering 1x1, 1x3 and 3x1 (#488).
    • Fixed: xcycsr_to_xyxy returns height 0 instead of inf on zero-aspect boxes via an r1 != 0 guard (#485).

    I/O & datasets

    • Fixed: VideoOutput resizes frames to the writer's configured size on mid-stream resolution change (INTER_AREA on downscale only) (#514).
    • Security: ZIP extraction is hardened against Zip Slip / path traversal (CWE-22) — archive members with absolute paths, traversal segments, empty names or Windows backslash paths are rejected, and validated archives cannot write outside the destination, including path-swap protection (#495).

    Packaging & docs

    • pydeprecate constraint raised from >=0.7.0 to >=0.8.0 — build backend migrated from hatchling to setuptools with src-layout discovery and py.typed support (#492).
    • Fixed: package builds for the src layout — corrected setuptools discovery and py.typed support, plus release CI artifact handling and publish triggers (#492).

    2.5.0 — 2026-06-24

    Trackers

    • Breaking: internal tracklet ID counters are removed — each tracker instance now allocates IDs. Internal *Tracklet subclassers should assign tracklet.tracker_id directly, using self._allocate_tracker_id() from BaseTracker in custom trackers (#419).
    • Deprecated: SORTTracker.trackers is an alias for .tracks — emits FutureWarning since 2.5 and is removed in 3.0. SORTTracker itself is not deprecated (#460).
    • pluggable IoU — iou= on SORTTracker, ByteTrackTracker, OCSORTTracker and BoTSORTTracker accepts any BaseIoU subclass (trackers.utils.iou), with built-ins IoU, GIoU, DIoU, CIoU and BIoU (Buffered IoU). Subclass BaseIoU and override _compute for a custom metric. Signed variants override normalize_for_fusion to shift [-1, 1] to [0, 1] before BoT-SORT score fusion (#403).
    • CBIoUTracker — Cascaded-Buffered IoU (Yang et al., WACV 2023): two-stage matching with independent buffer_ratio_first / buffer_ratio_second and BoT-SORT's ByteTrack-style low-confidence second pass (#417).
    • Fixed: BoT-SORT score fusion multiplied raw negative GIoU/DIoU/CIoU values by confidence and inverted track ranking — similarity is now normalized first (#403).
    • Fixed: non-finite box coordinates no longer reach linear_sum_assignment — BaseIoU.compute raises ValueError for NaN/inf (#403).
    • Fixed: OC-SORT observation-centric recovery uses standard IoU per the paper — independent of the configured iou= (#403).
    • Fixed: the IoU helper uses lazy np.divide(..., where=...) instead of eager np.where, suppressing RuntimeWarning on zero-area boxes under strict NumPy error settings (#403).
    • Fixed: ByteTrack produced no tracks when detections lacked confidence — the default fill is np.ones, as in SORT / OC-SORT / BoT-SORT (#415).
    • Fixed: tracker instances no longer share ID counters — so resetting one instance cannot reset another's allocator or duplicate live IDs in multi-camera, class-specific or parallel workflows (#419).

    Motion & utilities

    • CMC, CMCConfig and CMCMethod moved to trackers.utils.cmc and are re-exported from trackers (from trackers import CMC). BoTSORTTracklet.apply_cmc delegates to CMC.apply_batch, so per-track and batch paths share code; behavior is unchanged (#414).
    • CMC.apply_batch raises TypeError immediately on a tracklet list with mixed state-estimator types — preventing silent state corruption (#414).
    • Deprecated: removed in 3.0 (#414):
      • trackers.core.botsort.cmc re-exports with DeprecationWarning; use trackers.utils.cmc.
      • BoTSORTTracker.apply_cmc_batch; use CMC.apply_batch(H, tracker.tracks).
      • CMCTMethod; use CMCMethod.
      • CMC.apply_to_xyxy, renamed CMC.warp_xyxy_corners and kept as a forwarding wrapper.

    Evaluation

    • Fixed: the HOTA per-frame alpha loop is vectorized — so large evaluations run significantly faster with unchanged numeric output (#462).
    • Fixed: ground-truth preprocessing applies distractor class filtering consistent with TrackEval — correcting reported metrics on MOT17 and similar datasets (#466).

    Tuning

    • Tuner gains enqueue_defaults (default True, evaluates a baseline trial from each param's __init__ default before Optuna samples), fixed_params (held constant across trials), images_dir (frame loading for CMC-enabled trackers) and seed (reproducible TPE sampling) (#427).

    CLI

    • Fixed: iou= is excluded from argparse auto-discovery — so the BaseIoU parameter no longer crashes the CLI; set the variant programmatically (#403).

    Packaging & docs

    • py.typed marker (PEP 561) — so IDEs and type checkers treat the package as typed without --ignore-missing-imports (f93c0b0a).

    2.4.0 — 2026-05-07

    Trackers

    • Breaking: SORTTracker.update() no longer mutates its input sv.Detections and returns a fresh indexed copy, like ByteTrack and OC-SORT. Read tracker_id from the returned object (#360).
    • Breaking: per-frame spawn order is deterministic across SORT, ByteTrack and OC-SORT — IDs for same-frame spawns no longer depend on CPython set order. A recorded run reproduces across machines but may differ from a 2.3.0 baseline (#361).
    • Breaking: internal tracklets (notably OCSORTTracklet) no longer accept update(None) for unmatched tracks — missed-association logic lives in predict() and _get_alive_tracklets. Affects subclassers of internal *Tracklet classes only, not the public update() API (#383, #376).
